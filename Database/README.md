# SafePay Oracle Database Scripts

These scripts implement Phase 1 of SafePay using synthetic data only. Run them in this order against an empty Oracle schema:

1. `01_sequences.sql`
2. `02_tables.sql`
3. `03_constraints_indexes.sql`
4. `04_seed_data.sql`
5. `05_reporting_views.sql`

The database is the source of truth. The scripts provide structural constraints, while the Spring Boot service layer will enforce valid transaction transitions and authorization rules.

## Design decisions applied

- IDs are Oracle `NUMBER(19)` primary keys generated by sequences; the workbook's `U001`/`T001` style values are represented by readable seed ranges and transaction references.
- `FAILED` is included for simulated business and technical failures.
- `RELEASED` is an audited action that moves `PROTECTED` directly to `SETTLED`, not a lasting transaction status.
- Protection expiry is represented as a policy-driven transition to `SETTLED`; the backend will use server time to execute it.
- Risk configuration (`RISK_FACTORS`) and policy configuration (`PROTECTION_RULES`) remain separate.
- The `TRANSACTIONS` table retains historical records; no financial history is physically deleted.
