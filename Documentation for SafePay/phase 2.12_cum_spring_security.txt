### Recommended Phase 2.12 policies

- Use only user-specific destinations:

```text
/user/queue/notifications
/user/queue/transactions
/user/queue/risk-reviews
```

This is safer than shared customer topics and still supports Risk Officer queue refreshes.

- Use `notificationReference` as the client deduplication identity.
- WebSocket messages contain IDs, event type, safe state and timestamp—not balances, account numbers, internal notes or audit details.
- Persist the notification first. WebSocket delivery remains advisory.
- REST and Oracle remain authoritative after reconnect.
- Mark-read requires ownership and a row lock, but no `Idempotency-Key`; repeating it simply returns the already-read result.
- Global `/audit-logs` access should require `AUDITOR`. The combined administrator can use it because that persona separately holds `AUDITOR`.
- Customers receive only their safe lifecycle timeline. Risk Officers receive review-relevant context. Raw audit JSON is never returned directly.

### Recommended security policies

| Policy | Recommendation |
|---|---|
| JWT implementation | Official Spring Security OAuth2 Resource Server/Jose support; no custom JWT parser |
| Signing | `HS256` with a randomly generated Base64 secret of at least 256 bits, supplied only through environment configuration |
| Access-token validity | 15 minutes |
| Refresh-session validity | 7 days |
| Refresh token | Opaque `SecureRandom` value; only SHA-256 hash stored |
| Rotation | Every refresh replaces the old session |
| Replay response | Revoke the entire token family and reject the request |
| Failed-login threshold | 5 consecutive failures |
| Temporary lock | 15 minutes |
| Refresh cookie | `HttpOnly`, `SameSite=Strict`, path `/api/v1/auth`; `Secure=true` outside explicitly approved local HTTP |
| Access-token storage | Frontend memory only |
| CORS | Explicit configured development origins; never wildcard with credentials |
| WebSocket authentication | Bearer access token in the STOMP `CONNECT` header, never URL/query parameters |
| Security-version check | Compare JWT claim with current `APP_USER.SECURITY_VERSION`; reject locked, disabled or version-mismatched users |
