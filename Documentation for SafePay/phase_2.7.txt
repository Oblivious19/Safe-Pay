Critical review results:
The implementation now enforces:
- Unique scope by authenticated user, operation and idempotency key.
- Exact database status values: IN_PROGRESS, COMPLETED, and FAILED.
- Exact V4 sequence, table, column lengths, relationships, CLOB response storage and optimistic version mapping.
- Opaque, case-sensitive idempotency keys.
- Lowercase 64-character hexadecimal SHA-256 request hashes.
- Endpoint/action and concrete resource identity within the fingerprint.
- Stable hashes despite JSON whitespace or nested property-order differences.
- Array order preservation because array order may affect request meaning.
- Exact HTTP status, response body and transaction identity preservation.
- Safe 409 responses for a reused key with a different request or an already-running equivalent request.
- No idempotency key or request content exposure through error messages.
- UTC timestamps truncated to Oracle-compatible microsecond precision.
- Expiration becomes effective exactly at expires_at.
- No delete API on the idempotency repository.
